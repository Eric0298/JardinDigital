# Validación manual de JardinDigital personal v1

Esta matriz cubre la ampliación de Inicio, páginas de idea y recursos vinculados. **Pendiente de ejecución y registro en Tauri/WebView.** Las validaciones manuales anteriores documentadas en las notas de slices siguen siendo antecedentes; no acreditan estos nuevos flujos.

Utiliza una base desechable o exporta primero una copia y comprueba que existe. No borres la base real del usuario para simular una instalación vacía. Prueba tema claro y oscuro donde importe la presentación. Para cada fila registra resultado, versión probada y una captura o nota breve si falla.

| Flujo | Pasos | Resultado esperado |
|---|---|---|
| Inicio con 0, 1 y N jardines | Abrir con cada estado en una base desechable. Crear, abrir y renombrar jardines desde Inicio. Reiniciar. | La entrada siempre es Mis jardines; no se abre automáticamente el primero. Todos aparecen con nombre y acciones; los recuentos se corresponden con sus colocaciones. Con cero jardines se puede crear uno. |
| Navegación y castellano | Recorrer Inicio, Jardín, Buscar, Pendientes, Todas las ideas y Ajustes. Usar Nueva idea dentro y fuera del jardín. | Inicio y Jardín tienen protagonismo. Todas las etiquetas, formularios, confirmaciones y errores visibles están en castellano. Nueva idea en el jardín usa su lienzo; fuera permite guardar en pendientes. |
| Crear en jardín | Crear una idea con Nueva idea y otra con doble clic en el fondo. Probar Intro y Esc. Reiniciar. | Idea y colocación se crean juntas; las cancelaciones no crean registros. Las ideas y posiciones guardadas se recuperan. |
| Selección, arrastre y edición rápida | Seleccionar con un clic, arrastrar, hacer pan/zoom y Ajustar vista. Seleccionar una idea y usar Editar idea; probar Guardar, Esc y Ctrl/Cmd+Intro. | Un clic selecciona; arrastrar no abre la página. Las posiciones persisten. La acción explícita abre el editor rápido sin crear otra idea ni cambiar su identidad. |
| Página de idea y retorno | Hacer doble clic en una tarjeta y usar Abrir idea. Editar título/contenido, guardar y volver al jardín. Abrir también desde Buscar, Pendientes y Todas las ideas. | Se abre información, recursos, conexiones y jardines para la misma idea. Volver recupera el origen apropiado; los cambios guardados aparecen allí y tras reiniciar. |
| Cambios sin guardar | Editar una idea y navegar a Inicio, Buscar, otro jardín o una idea conectada; cancelar y luego aceptar el aviso de descarte. | Cancelar conserva el borrador y la página actual. Confirmar permite navegar sin guardar el borrador. Guardar antes de salir conserva los cambios. |
| Documentos locales | Añadir un documento desde el selector nativo, cancelar una selección, abrirlo y reiniciar. Quitar el recurso. | Se muestra icono, nombre y extensión/tipo. Abrir usa la aplicación asociada. Persisten referencia e identidad; no se copia el archivo. Cancelar no crea recurso. Quitar elimina metadata y conserva el original. |
| Vídeos | Añadir un vídeo local y otro mediante URL http/https; abrir ambos y reiniciar. | Ambos permanecen asociados a la misma idea. El local se abre en la aplicación asociada y la URL en el navegador. La tarjeta muestra una vista compacta con icono, nombre y tipo; no depende de FFmpeg. |
| Enlaces | Añadir una URL http/https con y sin nombre. Probar URL malformada, javascript, file y credenciales. Abrir y quitar un enlace válido. | El nombre opcional usa el dominio como alternativa; el dominio/URL ayuda a identificarlo. Los destinos no permitidos se rechazan con un error castellano. Abrir usa navegador externo; quitar sólo elimina la referencia. |
| Archivo ausente | Añadir un archivo desechable, cerrar la app, moverlo y volver a abrir la página. Intentar abrirlo. Devolverlo a la ruta y abrir de nuevo la página. | Se ve Archivo no disponible y la idea sigue editable. El recurso no desaparece ni rompe la carga. Una comprobación posterior permite abrir si la ruta vuelve a existir. |
| Recursos en lienzo | Asociar varios documentos, vídeos y enlaces; volver al jardín y reiniciar. | Las cantidades e iconos por tipo se actualizan y la tarjeta sigue compacta; no muestra todos los archivos. |
| Conexiones muchos-a-muchos | Crear A→B, A→C, D→A y B→D desde lienzo/página. Añadir A→A y un duplicado A→B. Abrir ideas conectadas y eliminar una conexión. | Persisten conexiones entrantes/salientes, auto-conexión y duplicados distintos. Abrir no duplica ideas. Eliminar una relación conserva las otras y todos los recursos. |
| Captura y pendientes | Guardar título, contenido o ambos; editar y reiniciar. Quitar una idea de pendientes. | Las ideas aparecen también en Todas las ideas. Quitar pendientes sólo elimina pertenencia; la misma idea conserva contenido, jardines, conexiones y recursos. |
| Procesar pendientes | Añadir una idea pendiente a un jardín. Repetir con una ya colocada desde Todas las ideas. | Se quita su pertenencia a pendientes y queda una sola colocación en ese jardín. Recursos y conexiones permanecen asociados a la idea original. |
| Todas las ideas y Buscar | Colocar una idea en dos jardines. Buscar título y contenido desde Buscar y Ctrl/Cmd+K; abrir un resultado y editar. Probar una consulta sin coincidencias y caracteres %, _ y barra inversa. | Se recuperan todas las ideas, incluidas las que no tienen jardín. Los resultados muestran contexto y abren la página con la misma identidad. El estado vacío y los caracteres literales se manejan correctamente. |
| Quitar colocación | Quitar de un jardín una idea colocada en dos, desde página, Todas las ideas o editor rápido. | Sólo desaparece esa colocación. Permanecen la idea, el otro jardín, pendientes, conexiones y recursos. Una conexión se muestra sólo donde están colocados ambos extremos. |
| Eliminar idea definitivamente | Preparar una idea con pendientes, dos colocaciones, conexiones entrantes/salientes y recursos. Cancelar una vez y confirmar después. Reiniciar. | Cancelar no cambia nada. Confirmar elimina idea y todas sus relaciones/metadata. Otros datos permanecen y los archivos originales siguen existiendo. |
| Eliminar jardines | Eliminar un jardín con ideas y recursos, cancelar una vez, luego eliminar el último jardín y crear otro. Reiniciar. | La eliminación confirmada quita lienzo y colocaciones. Ideas, conexiones, pendientes y recursos siguen recuperables. Inicio vacío funciona y permite crear otro jardín. |
| Apariencia y panel DEV | Probar Sistema/Claro/Oscuro y Liso/Puntos/Cuadrícula, reiniciar y revisar detalles de desarrollo en claro/oscuro. Revisar una compilación de producción. | La apariencia persiste y Sistema sigue al SO. En DEV el panel es legible; en producción no hay paneles técnicos ni IDs internos. |
| Copia v2 y restauración | Guardar copia en una ubicación conocida, verificar marcador/version 2 y metadata de recursos. Hacer cambios; cancelar restauración y después confirmarla. Reiniciar. | El JSON existe y no contiene bytes de los archivos externos. Cancelar conserva el estado actual; confirmar recupera identidades, contenido, jardines, pendientes, conexiones, recursos y apariencia, y vuelve a Inicio. |
| Restauración con archivo ausente | Exportar una copia v2 con recurso local, mover el archivo desechable y restaurarla. | Se restaura su referencia sin copiar ni recrear el archivo. Su página muestra Archivo no disponible y conserva la idea. |
| Compatibilidad v1 | En una base desechable con recursos actuales, restaurar una copia v1 anterior válida. | Se recupera el estado de v1, sin recursos; la metadata actual queda sustituida y los archivos externos permanecen intactos. |
| Restauración inválida | Probar JSON malformado, versión incompatible, campos inesperados, referencias rotas, recurso con URL no permitida y v1 con recursos no vacíos. | Se rechaza cada intento con mensaje castellano; todo el estado actual sigue utilizable y sin cambios parciales. |
| Errores y accesibilidad | Navegar con teclado; revisar foco, labels y botones ocupados. Provocar un error recuperable en una base desechable cuando sea posible. | El foco es visible, los controles están etiquetados, las operaciones destructivas piden confirmación y los errores no exponen SQL ni IDs técnicos. |

La atomicidad ante fallos de escritura y el rollback se verifican también en tests; no hace falta manipular la base real para forzar errores. Anota por separado los resultados automatizados y los del recorrido de escritorio.
